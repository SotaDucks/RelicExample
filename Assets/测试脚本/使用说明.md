# Kaoru 俯视角控制与 Animator

已通过 Unity 官方 CLI 将控制器部署并保存到 **Assets/Scenes/Demo.unity** 的 **Kaoru**。直接进入 Play 模式即可使用，Gameplay Camera 已绑定到渲染世界的 PixelCamera。

## 操作

- **W / A / S / D**：相对于游戏相机奔跑，支持斜向等速、加速和减速。
- **鼠标左键**：朝鼠标对应的水平地面方向播放一次 AttackA1。点击 UI 不攻击。
- 攻击期间停止水平移动并固定攻击朝向。重复点击不打断、不重启当前动作；完整播放并结束过渡后，按当前按键恢复奔跑或待机。

攻击动作对应展示面板的 **AttackA1**，素材名称是 **Atk_A1_wing**。本功能负责移动、朝向和动作播放，未实现敌人伤害判定。

## Animator 中的配置

打开本文件夹的 **KaoruGameplay.controller**。Base Layer 包含 Idle、RunA、AttackA1 三个状态，Idle 为默认状态，六条真实的状态连线已经建立：

| 连线 | 条件 | Has Exit Time | 过渡时间 |
| --- | --- | --- | --- |
| Idle → RunA | IsMoving = true | 关闭 | 0.12 秒 |
| RunA → Idle | IsMoving = false | 关闭 | 0.12 秒 |
| Idle → AttackA1 | Attack Trigger | 关闭 | 0.06 秒 |
| RunA → AttackA1 | Attack Trigger | 关闭 | 0.06 秒 |
| AttackA1 → RunA | IsMoving = true | 开启，Exit Time = 1 | 0.10 秒 |
| AttackA1 → Idle | IsMoving = false | 开启，Exit Time = 1 | 0.10 秒 |

所有过渡均采用固定秒数。攻击进入条件优先于移动条件，允许从待机与奔跑的混合中响应攻击。攻击本身和攻击恢复过渡不允许中断，也没有 Any State 自循环。

四个 Animator 参数为 **IsMoving（Bool）**、**Turn（Float）**、**Attack（Trigger）**、**AttackSpeed（Float，默认 1）**。脚本只写参数，攻击锁定根据当前及下一个 Animator 状态的 Attack Tag 判断，不再按动画长度倒计时，也不调用 Play/CrossFade 强制切换状态。

双击 **RunA** 状态可打开一维 Blend Tree：

| Turn 阈值 | 动画 |
| --- | --- |
| -1 | RunA_L_wing |
| 0 | RunA_wing |
| +1 | RunA_R_wing |

左右根据角色的物理朝向与目标移动方向之间的有符号夹角判断。左转使用 RunA_L，右转使用 RunA_R，对齐后回到 RunA；180° 掉头延续上一转向侧，避免左右抖动。三个片段共享播放进度，转向时不重新起跑。转向速度从旧配置的 1080°/秒调整为 540°/秒，让转向动作有可见的播放时间。

**AttackA1 的状态 Speed 已从旧配置的 5 恢复为 1**，只由 AttackSpeed 参数控制攻击倍率。KaoruAttack.anim 是独立的非循环片段，退出时间等于完整动作的归一化时长 1。原始 FBX 保持不变。

## 组件调节

在 KaoruTopDownController 上可调整：

- Run Speed：目标奔跑速度，默认 4。
- Turn Speed：物理转身速度，当前 540°/秒。
- Acceleration / Deceleration：水平加速和停止速率，默认 28 / 40。
- Full Turn Animation Angle：转向片段达到完整目标权重的夹角，默认 45°。
- Turn Animation Damping：转向动画混合的平滑时间。
- Attack Speed：仅影响攻击状态的倍率，范围 0.1–3。
- Face Mouse When Attacking：是否按点击方向攻击。

角色使用 Rigidbody 和 CapsuleCollider 与 3D 地形碰撞，保留重力、冻结刚体旋转，Root Motion 关闭。Gameplay Camera 应为渲染世界的 **PixelCamera**，不要选择最终输出画面的 ViewCamera。

## 相机跟随

Demo 场景的 **PixelCameraSystem** 已挂载 **KaoruPixelCameraFollow**，Target 为 Kaoru。跟随只移动这个父级，保持场景里原有的镜头偏移和旋转角度。PixelCameraManager 继续使用同级的 **PixelCameraTransform** 作为内部锚点，并负责 PixelCamera 的网格对齐及亚像素校正。

跟随在 LateUpdate 中读取角色经过刚体插值的位置，执行顺序为 -100，先移动父级，再由 PixelCameraManager 完成像素校正。Smooth Time 默认 0.12 秒，设为 0 可立即跟随；Follow Height 决定是否跟随地形高度。角色转身不会旋转镜头。

在其他场景手动布置时，将 KaoruPixelCameraFollow 挂到 **PixelCameraSystem**，将角色拖到 Target，并在进入 Play 前摆好镜头位置。也可选中角色，执行 **Tools > Kaoru > Configure Camera Follow**，再保存场景。完整的 Configure Selected Character 菜单也会配置这项绑定。

## 重新部署或给其他角色配置

1. 在场景选中 Kaoru 根对象，或选中其模型子对象。
2. 执行 **Tools > Kaoru > Configure Selected Character**。
3. 保存场景。

工具会更新本文件夹专用 Animator 的状态、连线、参数和 Blend Tree，保留控制器 GUID、根状态机、已有状态节点和 Blend Tree 的引用，重新绑定相机和角色组件。这样在 Animator 窗口打开时重复部署，也不会因面包屑引用失效而显示空白。已存在的独立攻击片段会保留；重复部署不会增加重复状态或连线。

## 已完成的验证

Unity 编辑器编译通过。使用 Input System 的临时虚拟键鼠进行了 **29 个实际 Play 模式步骤**：直跑、右转、左转、180° 掉头、斜跑、松键停止、待机攻击、跑动攻击、攻击中重复点击、攻击中松键、攻击后继续跑、禁用再启用，以及 2 倍攻击速度。

运行记录中，奔跑的归一化播放进度在连续转向时持续增长；普通攻击含过渡约 1.27 秒，2 倍速约 0.69 秒，攻击锁定期间水平速度为零。转向片段及攻击截图也已核对。

进入 Play 模式后，可执行 **Tools > Kaoru > Verify In Play Mode** 重跑验证。验证会临时接管输入并移动角色，请等待完成；随后恢复角色位置、朝向、输入设备及攻击倍率。报告和截图写到项目 **Temp/KaoruAnimatorVerification/**，不会加入游戏资源。

项目另有既存的 **URP-Stylized-Renderer 缺少 RendererFeatures** 提示，本次未修改渲染器。
